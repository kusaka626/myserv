# Установка, данные и восстановление

## Изменения на VPS

* Устанавливаются системные пакеты, Docker и проверенный по SHA256 K3s.
* Создаётся `myserv-k3s.service`, Kubernetes namespace `myserv`, Secret `tunnel`, Deployment `tunnel` (1 replica, Recreate).
* `/var/lib/myserv` — 0700; `state.json`, серверные конфигурации и клиентский профиль — root-only. Kubernetes secrets encryption включён.
* `/var/log/myserv-setup.log` — журнал установки с umask 077; секретные конфигурации туда не печатаются. При ручной передаче журнала проверьте его содержимое.
* Для AWG включается IPv4 forwarding (`/etc/sysctl.d/90-myserv.conf`), запускается TUN и правила NAT/FORWARD для `10.78.0.0/24`. Контейнер имеет hostNetwork и privileged: используйте выделенный VPS.
* Xray работает как UID 65532, root filesystem read-only, без service account token и без лишних capabilities; сохраняется NET_BIND_SERVICE для 443.
* Kubernetes API/kubelet/служебные адреса ограничены loopback. В firewall хостинга нужны только SSH и выбранный VPN-порт. Правило UFW добавляется только если UFW уже активен; firewall не отключается.

## Повтор после ошибки

Подключитесь с тем же IP и SSH host key, используйте ту же лицензию и протокол, запустите установку повторно. На сервере есть `flock`, поэтому конкурентная установка отклоняется. Сохранённый `state.json` используется повторно; существующие private keys не заменяются. Изменение протокола или binding отклоняется. Откат всего VPS автоматически не выполняется: возможна частично завершённая установка, которую нужно повторить/диагностировать.

Проверка через консоль хостинга:

```sh
systemctl status docker myserv-k3s
journalctl -u myserv-k3s --no-pager -n 100
k3s kubectl -n myserv get pods
k3s kubectl -n myserv describe deployment tunnel
k3s kubectl -n myserv logs deployment/tunnel --tail=100
```

Не публикуйте `state.json`, Kubernetes Secret, QR и конфигурации. При утрате клиентского файла повторная установка с прежней лицензией вернёт прежний профиль. Перед переустановкой ОС экспортируйте профиль и лицензию; смена host key требует новой привязки/ручного восстановления у оператора.

## Удаление

Сначала сохраните нужные данные. Не удаляйте весь Kubernetes/Docker на сервере, куда после MyServ добавляли другие приложения. Для остановки только VPN: `k3s kubectl -n myserv scale deployment tunnel --replicas=0`. При штатном завершении AWG удаляет свои правила NAT/FORWARD и интерфейс. При аварийном завершении проверьте оставшиеся правила перед ручным изменением сети.

## Ограничения безопасности

Host fingerprint сверяется через независимую консоль перед авторизацией. Вход root используется только на выделенном VPS, затем пароль/ключ SSH удаляется из памяти при завершении сеанса. `zeroize` очищает Rust-структуру; это не гарантия полного стирания всех копий из WebView/ОС. Журналирование секретов и телеметрия конфигураций отсутствуют. Экспортированные файлы и буфер обмена остаются ответственностью владельца устройства.

Состояние оплаты сохраняется локально для восстановления заказа. На Windows действуют ACL профиля пользователя; на Unix — права 0700/0600. В production оцените шифрование хранилища ключом Keychain/Keystore/DPAPI и политику резервных копий.
