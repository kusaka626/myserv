# Проверки этой версии

Проверено в облачной Linux-среде 6 ноября 2026 года. Это preview, не подтверждённый коммерческий релиз.

## Обновление 0.1.4 — ожидание dpkg

* Журнал VPS пользователя подтвердил отсутствие BuildKit в старой сборке и отдельный отказ повторной установки из-за блокировки `dpkg/lock-frontend` процессом `unattended-upgr`.
* Для обеих команд установки пакетов задан штатный `DPkg::Lock::Timeout=600`. Установщик не удаляет блокировки и не завершает чужие процессы.
* `scripts/apt-lock-smoke.py` проверяет в одноразовой Ubuntu 24.04 реальные POSIX-блокировки `lock-frontend` и `lock`: apt остаётся в ожидании, после освобождения завершается успешно, inode файлов блокировки сохраняется. Проверки ошибок установщика, frontend build и 4 Vitest-теста — успешно.
* Windows x64 0.1.4 собран. Полная установка на VPS пользователя и запуск EXE на Windows в этой сессии не выполнялись.

## Обновление 0.1.3 — установка Buildx и диагностика

* Воспроизведён отказ legacy Docker builder на `RUN --mount`. Установщик AmneziaWG теперь явно устанавливает `docker-buildx` и включает BuildKit. Установка `docker.io` и `docker-buildx` проверена в одноразовом Ubuntu 24.04; `docker buildx version` выполнен успешно.
* Реальный install.sh проверен в изолированных контейнерах со специально остановленной установкой пакетов и некорректным состоянием. В SSH-ответ приходят этап, числовой код и строка; содержимое конфигурации не передаётся в сообщение ошибки. Проверка сохранения ключей при повторе — успешно.
* 10 Rust-тестов с free-preview, Clippy, rustfmt, shell syntax, frontend build и 4 Vitest-теста — успешно. Windows x64 release пересобран.
* Полный прогон Docker/K3s/VPN на внешнем VPS и запуск Windows EXE не выполнялись. Исправление Buildx подтверждено локально; связь с конкретным сбоем пользователя требует журнала его VPS.

## Обновление 0.1.2 — бесплатная тестовая настройка

* Rust workspace с `myserv-core/free-preview`: 9 тестов. SSH-стенд проверяет путь установки без лицензии до возврата тестового профиля и отказ обычного платного пути без лицензии до SSH. Стенд имитирует команды установки, не настраивает внешний VPS.
* TypeScript/Vite, 4 Vitest-теста, Clippy и rustfmt. Браузерный мастер проверен в обоих режимах: бесплатный пропускает оплату, не вызывает платёжные команды и передаёт пустую лицензию; согласие на изменение VPS остаётся обязательным.
* Windows x64 release EXE 0.1.2 собран с `free-preview` и `custom-protocol`. Обычная нативная сборка без `free-preview` проверена через `cargo check`.
* Запуск на Windows, полная установка на внешнем VPS и внешний VPN-трафик в этом прогоне не проверялись. Тестовый режим разрешает настоящую установку на VPS пользователя без оплаты; платёжные запросы блокируются.

## Обновление 0.1.1

* `cargo test --workspace --locked --offline`: 9 тестов прошли; отдельный OpenSSH-тест запускается через `bash scripts/ssh-smoke.sh`.
* Настоящий локальный OpenSSH: вход root, вход ubuntu с паролем sudo, выполнение команды от UID 0, сохранность скрипта и пароля со спецсимволами, отказ пользователю без sudo и понятная ошибка нехватки RAM — успешно.
* SSH: первое автоматическое запоминание, повторное подключение, отклонение несовпадающего сохранённого ключа до передачи пароля — успешно.
* TypeScript/Vite, 3 Vitest-теста, браузерный мастер с четырьмя полями и тестовыми native-вызовами, Clippy, rustfmt и shell syntax — успешно.
* Нативный Tauri: Linux `cargo check` в контейнере — успешно. Windows x64 release EXE версии 0.1.1 с `custom-protocol` пересобран после исправления sudo; упакован вместе с WebView2Loader.dll.
* Проверки выполнялись на Linux и локальных контейнерах. Запуск EXE непосредственно на Windows и установка на внешнем VPS пользователя не выполнялись. ЮKassa в скачиваемой preview-сборке не настроена; платная установка остаётся недоступна.

## Не проверено и что нужно для приёмки

* Полная цепочка покупки/настройки на внешнем **чистом Ubuntu 24.04 VPS**: Docker, K3s, systemd, firewall, reboot, потеря SSH и повтор. В этой сессии внешний VPS и его доступ не предоставлялись. Проверки контейнеров не заменяют этот прогон.
* Настоящий оплаченный заказ ЮKassa, фискальный чек, отмена/возврат и production HTTPS billing. Аккаунт магазина, ключи и налоговая конфигурация не предоставлялись; деньги не списывались.
* Windows runtime, Android APK/device lifecycle, iOS IPA/симулятор/устройство, file picker/clipboard/QR import на всех ОС, магазинные покупки. CI добавлен, но в GitHub здесь не запускался.
* Внешний полный VPN-трафик, скорость, DNS/IPv6 leak tests, firewall провайдера и поведение REALITY в конкретной сети.

## Повторить

```sh
bash scripts/check.sh
bash scripts/protocol-check.sh       # нужны Docker и /dev/net/tun
bash scripts/native-check.sh         # Linux + Docker + rustup
python3 scripts/state-smoke.py       # использует образ myserv-native-check
python3 scripts/ui-smoke.py          # Vite на 1420, Python Playwright и Chromium
```

В managed cloud используйте штатный proxy/CA и разрешение executor на локальные сокеты. Во время установки `npm ci` остановите Vite, затем запустите его снова. Тестовый native-adapter существует только в `scripts/ui-smoke.py`, не в production-приложении.
