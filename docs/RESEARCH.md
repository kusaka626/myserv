# Исследование и принятые решения

Проверено 6 ноября 2026 года. Репозиторий изначально был пуст.

## Что именно создаём

MyServ — приложение для обучения покупке VPS и автоматической установки ПО на **собственный** сервер пользователя. У сервиса нет общего пула VPN-серверов. Клиент устанавливает один протокол, выдаёт конфигурацию/ссылку/QR. Само приложение пока не маршрутизирует трафик устройства: нужен совместимый клиент AmneziaWG 3.1 или Xray.

199 ₽ — разовая услуга настройки одного VPS, включая безопасные повторы на том же IP и SSH host key. Аренда VPS оплачивается хостингу отдельно. Один профиль соответствует одному клиенту; для нескольких одновременно подключённых устройств нужны отдельные peers, их управление в эту версию не включено.

## Проверенные источники

* [AmneziaWG Go README](https://github.com/amnezia-vpn/amneziawg-go): у 3.x есть `HeaderProtectionKey`, `ContentPaddingAddition`, S1–S4. Для защиты заголовков все S должны быть не меньше 12. Проверены README, код UAPI и опубликованные Git-теги.
* [amneziawg-go v3.1.20260828](https://github.com/amnezia-vpn/amneziawg-go/tree/v3.1.20260828), commit `b5928efb6ca19f0153958460c3d141f04abc5c2e`.
* [amneziawg-tools v3.1.20260812](https://github.com/amnezia-vpn/amneziawg-tools/tree/v3.1.20260812), commit `ee0f0a9aa34ff0a0da4b3433b9512781cfe02843`. Makefile выпускает `wg`; в нашем образе он установлен как `awg`.
* [REALITY](https://github.com/XTLS/REALITY/blob/main/README.en.md) и [Xray v26.10.31](https://github.com/XTLS/Xray-core/tree/v26.10.31). Изучены описание протокола и официальный Dockerfile. Серверный `target`, клиентский `password` и VLESS-параметр `pbk` проверены настоящим бинарником Xray.
* [K3s](https://github.com/k3s-io/k3s): проверены теги и установщик. Выбран `v1.34.13+k3s1`, бинарники сверяются с официальным SHA256-файлом релиза. Флаг `--docker` использует Docker через cri-dockerd, а не встроенный containerd.
* [russh](https://github.com/Eugeny/russh): изучен официальный SSH-пример и API установленной версии 0.65.1. В отличие от демонстрационного примера, ключ сервера проверяется перед передачей учётных данных.
* [ЮKassa SDK](https://github.com/yoomoney/yookassa-sdk-python) и [API](https://yookassa.ru/developers/api): модель redirect/capture, idempotence key, проверка состояния через API. Реальные операции требуют магазина и ключа; коммерческий платёж в этой среде не выполнялся.
* [Tauri 2](https://v2.tauri.app/), исходники установленных `tauri`, `tauri-plugin-dialog`, `tauri-plugin-fs`: общий Rust backend, системный WebView; диалоги и файловый адаптер поддерживают мобильные document URI.

## Почему так

| Область | Решение |
| --- | --- |
| Общее ядро | Rust crate `myserv-core`, без UI-зависимостей; используется CLI и Tauri |
| Клиент | Tauri 2: Windows, Android, iOS; интерфейс HTML/CSS/TypeScript, бизнес-логика Rust |
| SSH | Нативный async `russh`, без внешнего ssh.exe и shell на устройстве |
| ОС сервера | Чистая Ubuntu 24.04, systemd, root, IPv4, x86_64/aarch64; минимум 2 ГБ RAM и 8 ГБ свободно; рекомендуются 2 vCPU и SSD 20 ГБ |
| Контейнеры | Docker + одноузловой K3s. Это тяжелее обычного Docker Compose, но выполняет требование Kubernetes |
| AmneziaWG | Userspace Go/TUN вместо установки модуля ядра; контейнеру нужны привилегии NET_ADMIN/доступ к TUN; Kubernetes-вариант privileged |
| Сеть | hostNetwork для фиксированных VPN-портов, host-gw CNI без VXLAN, Kubernetes API и kubelet на loopback |
| Ключи | CSPRNG, X25519; конфигурация сохраняется на принадлежащем пользователю VPS с правами root; без вывода секретов в журнал |
| Деньги | Отдельный Axum API + SQLite + ЮKassa; сумма только на backend; подписанная Ed25519-лицензия привязана к IP и SSH host key |
| Повторы | Клиент сохраняет идентификатор заказа и capability-token в app data; сервер не пересоздаёт ключи; SQLite хранит idempotency/provider ID |

## Ограничения до выпуска

* Это первая рабочая реализация, не опубликованный коммерческий продукт. Полная установка на чистом VPS, фактический доступ из внешних сетей, перезагрузка VPS и восстановление после обрыва требуют отдельного приёмочного прогона.
* Для iOS нужны macOS/Xcode, Apple Developer account, идентификаторы и подпись. Для Android — SDK/NDK/JDK и подпись. Для Windows — WebView2 и подпись установщика. CI описывает сборку; наличие конфигурации CI не означает, что она уже выполнялась.
* Встроенная покупка цифровой услуги в App Store/Google Play зависит от storefront, правил и применимых программ внешних платежей. До проверки выбранного канала дистрибуции мобильные покупки отключены. Нельзя обещать, что размещение ссылки на ЮKassa автоматически допустимо. Импорт ранее полученной лицензии технически реализован; его допустимость также проверяется перед публикацией.
* Ставка НДС, онлайн-касса, чек, оферта, возвраты и политика обработки данных определяются владельцем магазина. Ставка не угадывается: `MYSERV_VAT_CODE` обязательна.
* Подписанная лицензия проверяется офлайн. Автоматического отзыва после возврата нет. Сервер полностью контролируется пользователем, а открытый клиент можно изменить: это не DRM и не способ навязать платную подписку на уже установленное ПО.
* Проверка REALITY TLS выполняется перед запуском контейнера. Пользователь выбирает доступный с VPS домен с TLS 1.3 и HTTP/2; устойчивость к блокировкам не гарантируется.
* AWG-профиль направляет IPv6 в туннель, но VPS настроен только на IPv4. Полноценный IPv6 и проверка утечек для конкретного клиента остаются отдельным этапом приёмки.
* Нет автоматического продления VPS, обновления протоколов, ротации/отзыва peers, миграции между протоколами и массового управления серверами. Переключение уже установленного протокола намеренно отклоняется, чтобы сохранить рабочие ключи.
